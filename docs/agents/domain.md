# Domain docs

## Layout and reading

This repository uses a single context: root `CONTEXT.md` and `docs/adr/`.

Before exploring the domain, read `CONTEXT.md` and ADRs relevant to the
area being changed. If these files are absent, proceed silently.
Domain-modeling creates them when terminology or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, code and tests.
If a needed concept is missing, flag the gap for domain-modeling.

## Decisions

Surface contradictions with existing ADRs explicitly, naming the ADR
and explaining why its decision should be reconsidered.
